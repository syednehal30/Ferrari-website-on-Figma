# ZanDop — Local Agency Workspace

Free, MIT-licensed agency workflow software for Windows: personal Gmail outreach, a client email inbox, service-specific questionnaires, manual quotes starting at **$500 USD**, branded PDFs, project starters, quality checks, Payoneer request approvals, and a shared CRM. Your data stays on your computer. No Instantly, Smartlead, extra domain, paid hosting or paid AI API is required for the local workflow.

**Start here: [Windows setup](WINDOWS-START-HERE.md).** Use **Start ZanDop.bat** (or **Start ZanDop Workspace.bat**) for real clients. **Open ZanDop Demo.bat** explicitly opens the separate fictional demo. The real workspace starts with email automation paused and no sample clients.

This is an operational workflow application with bounded automatic replies, not a guarantee that an entire agency or every client conversation can run without intervention. Deliverables are unpublished starters and drafts that need final human review. Live Gmail and Payoneer transactions have not been tested with the owner's accounts.

| Client Success | Generate personalized welcome PDFs and project plans from questionnaire answers or call notes. Discovery can happen entirely by email; the owner hosts video calls. |

The weekly target is **two new $500+ projects**, with at most two active projects. Accepting an approved quote reserves a slot; extra acceptances wait for capacity. New outreach pauses while full, but existing conversations continue. Daily and weekly counters use Asia/Karachi time. This is an operating target, not a promise of clients or income.

SQLite and locally generated PDF documents are the free defaults; Google Docs/Sheets and Google Calendar OAuth are not connected. The owner adds confirmed call slots and video links to their calendar.

## Gmail and reply timing

The local workspace uses Gmail IMAP over TLS on port 993 and SMTP over TLS on port 465. Enable Google 2-Step Verification, create an app password, and enter it only in the local dashboard. App passwords may be unavailable on some managed or restricted Google accounts. OAuth login is not implemented.

Create a dedicated **ZanDop** label, expose it to IMAP, and route client messages there with Gmail filters. The first connection test establishes a starting position without replying to old mail. Subsequent new messages in the label are recorded, including new client inquiries. After outreach is enabled, new INBOX headers are checked for delivery notices and replies from known outreach recipients. Only those relevant message bodies are imported; unrelated personal message bodies are not read. Known-prospect replies continue to be processed when new outreach is disabled. Email attachments are not downloaded automatically; oversized messages are flagged for review. Automated senders, mailing lists, self-mail and ordinary autoresponders are ignored.

Gmail is checked every 60 seconds. New outreach requires a successful delivery-notice check within five minutes and a reviewed draft. A permanent delivery-status notice stops new outreach immediately; there is no requirement to buy a warm-up service. This does not guarantee inbox placement or prevent Gmail restrictions. Five minutes is a reply target while the PC is awake, online and able to process its workload, not a delivery guarantee. A separate mailbox worker prioritizes replies ahead of project work. Pause all automation or an individual conversation at any time. Gmail has sending and usage limits. Closing the command window, shutting down or sleeping stops processing; persisted mailbox positions allow catch-up after restart.

Automatic replies use bounded templates and CRM facts, with no model subscription. They handle common discovery, status, assets, scheduling and acknowledgment messages. Complex or unclear requests may receive a clarifying question; financial, legal and scope-change requests go to the owner. WhatsApp, Instagram, LinkedIn DMs and webchat are not connected. The agent cannot attend video calls.

## Money and approval guarantees

Money uses integer USD cents. The $500 minimum is enforced by the API and approval handler. Editing a quote invalidates its previous unsent authorization, client acceptance and derived project artifacts. The client accepts a specific quote reference; a generic acknowledgment is not treated as acceptance.

All proposals, payment requests, custom owner-composed replies, legal content and final delivery require explicit review. Potential financial material in an otherwise routine document is held for approval. Generated routine messages do not negotiate prices. Approval binds to the exact payload, recipient and attachment hash. Changed attachments cannot silently reuse an old approval.

Payoneer integration is a **manual request-link workflow**, not an API connection. The owner creates the request in Payoneer, checks its amount and recipient, adds its official HTTPS link, and approves the email. A client saying “paid” never marks a project paid. Receipt verification requires the owner's checkbox, matching amount and transaction reference. Payment-request availability and Payoneer fees depend on the owner's account. ZanDop does not charge cards, withdraw funds, sign contracts, or generate legal agreements.

Each outgoing action is committed as `sending` before the provider call. An uncertain send is held without automatic retry. Inspect Gmail's Sent folder, then use **Client inbox → Resolve send status** to record what happened. New financial content always requires a new approval. Gmail accepting a message does not prove delivery to the recipient.

## Windows storage and operation

Python 3.12 is required. The launcher installs pinned dependencies in `.venv-local` and reuses them. Installed Edge/Chrome supplies the browser used for quality checks; otherwise Playwright downloads Chromium. First installation needs internet access.

- Real workspace: `%LOCALAPPDATA%\ZanDop\workspace`
- Demo: `%LOCALAPPDATA%\ZanDop\demo`
- Database, PDFs and delivery files are stored together in the selected data directory.
- Gmail app passwords are encrypted with Windows DPAPI for the current Windows user. They are never returned by the API or placed in source code. A different Windows account or computer must reconnect Gmail after restoring a backup.
- The local server binds only to `127.0.0.1`, uses a per-launch operator credential and a one-time browser sign-in, and rejects cross-origin mutations. One process per workspace is enforced by a file lock.
- **Enable Windows Auto-start.bat** adds a shortcut for the current user's Windows sign-in. **Disable Windows Auto-start.bat** removes only that shortcut. No administrator account or Windows service is required.

Do not expose this local server to the internet. Back up the whole data directory while the app is stopped. No credentials, runtime databases or private client files belong in Git.

## Local AI for individual first emails

For individually written first emails and content drafting, install [Ollama](https://ollama.com/), download a model suited to your hardware and permitted use, and enter its model name in **Local setup**. The app talks only to `127.0.0.1:11434` for this mode. For example, install a model with `ollama pull qwen2.5:7b`, then save `qwen2.5:7b` in Local setup. There is no automatic model download or paid fallback. Routine client replies work without a model; first-email drafting requires one. Model licenses, disk use, memory needs and generation speed vary. Drafts still need factual and final review. Local-model research/drafting runs without holding the client email lock. A failed draft is flagged for manual retry, rather than silently replaced with a template.

## Development and verification

On the prepared cloud/Linux checkout:

```bash
bash scripts/install.sh
bash scripts/run.sh
make test
.venv/bin/python tests/browser_smoke.py
.venv/bin/python tests/local_browser_smoke.py
```

For the local launcher: `python scripts/local_demo.py` opens the real workspace by default; use `--demo` for the separate fictional demo. The existing `--workspace` option remains supported. The real launcher ignores `.env` and starts with local settings; advanced cloud adapters use the existing environment-based scripts. Use the existing checkout; cloud tasks are isolated and do not require worktrees.

Tests exercise the complete demo and email-only journey, actual PDFs, Gmail parsing/polling and SMTP behavior with fake transports, price floor, quote revision, client acceptance, exact-payload/attachment approval, Payoneer confirmation, replay protection, uncertain sends, daily sending limits, exact outreach reviews, project capacity, delivery-status suppression, selective inbox import, public contact discovery, auth and browser controls. No tests send real email or payments. Linux bootstrap and browser behavior are tested here; actual Windows launcher/DPAPI behavior and account-specific Gmail authentication still need verification on the owner's PC.
